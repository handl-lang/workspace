# Audit: repo-family architecture consistency (2026-11-20)

User-provided audit — reference, not absolute truth. Feeds P-001 / the
weekend epic sweep ordering.

## Consistent

`engine-*`, `ext-*`, `sdkgen-*`, `host-*`, Rust `kit-*`, Python packages —
naming, edition, license, layout, and `ci.sh` templates hold within each
family.

## Inconsistent

### `lib-*` (worst) — ~6 architectures coexist

- `lib-{bytes,cmp,error,mood,obj}`: real Rust crates, no `pkg.hnl`/CI/LICENSE —
  kernel substrate ops in `lib-` clothing.
- `lib-{arrow-iter,datetime,encoding,stats}`: `ci.sh` runs `cargo test` but no
  `Cargo.toml` → gate broken.
- Unresolvable `pkg.hnl` modules: `lib-comb`, `lib-posix-c`, `lib-posix-stub`,
  `lib-ip` (partial), `lib-curl`, `lib-libc`, `lib-libz` (no `.hnl` at all).
- Legacy `handl-packages/` layout, no `pkg.hnl`: `lib-{command,event,query,
  otlp}` (+ `lib-otlp` has both).
- 15 `handl-plugin-lib-*` native crates vs ~30 const-only `handl-lib-*` vs 68
  pure `.hnl` — three crate models.
- ~40 crates declare `MIT OR Apache-2.0` but ship only MIT `LICENSE`;
  `sdkgen-file` missing `LICENSE-MIT`.
- Stray `../../lib-*` relative imports in `lib-{posix-c,noise-c,unicode-c,ffi}`;
  empty `hnl-gate.sh` in `lib-url-rfc`; `.kuda/` committed in only ~34 repos.

### `kit-*`

Rust-workspace vs Python split is fine, but 6 Python kits have no
`bupha.toml`/CI (`kit-kernel-ir` does); crate dirs split `kit-*` vs
`handl-kit-*`; `kit-{core,ffi,lang,pkg,server,stdlib,test}` lack LICENSE files
+ README.

### `compile-*`

workspace+`modules/` layout (`dot`, `handl`, `sexp`, `term`) vs flat
(`js`, `llvm`, `cuda`, `triton`); `compile-{cuda,triton}` are edition 2021,
non-`handl-plugin-` names.

### Bare repos

`host`/`kernel` use `scripts/ci.sh` (third CI layout); `eqsat`, `gamekit`,
`discoverykit`, `mlopt`, `host-tensor`, `test` have no `bupha.toml`.

### Doc drift

`structure.md` counts stale (120 lib, 18 kit, 16 engine).

## Top fixes (audit ordering)

1. broken `ci.sh` ×4
2. unresolvable `pkg.hnl` ×6
3. lib crate-model decision
4. license metadata
5. migrate `handl-packages/` repos
